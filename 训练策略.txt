Qwen3-4B 中文短剧专用模型：完整实施步骤与训练策略
一、项目目标与总体路线
目标不是训练一个通用中文模型，而是在现有指令模型基础上，通过高质量监督微调，让它更稳定地完成中文短剧创作任务。

目标作品：每集 1–3 分钟的中文短剧。

第一阶段只验证三项核心能力：
1. 单集生成：根据人物、背景、剧情要求，生成完整一集。
2. 场景续写与改写：根据已有剧本，续写或重写指定场景。
3. 按指令修改：根据明确要求调整对白、动作、节奏、冲突等，同时保持其他内容不变。
暂不纳入第一阶段：
- 故事大纲生成
- 长篇人物设定与关系设计
- 多集连续剧情规划
- 剧情逻辑审查
- 小说到短剧的完整改编
- 独立的错误诊断与纠错任务
- CPT（持续预训练）
- 知识蒸馏
这些任务可以进入第二阶段，但不应在第一轮同时铺开。
总体流程
1. 确定模型与训练环境
   
   Qwen3-4B-Instruct-2507、Kaggle T4、QLoRA。
2. 制定剧本规范
   
   固定剧本结构、场景头、人物表、对白、动作、集尾悬念。
3. 建立数据标准
   
   JSON Schema、数据元信息、格式校验器。
4. 制作人工金标准
   
   手写30–50条高质量样本，建立风格和质量参照。
5. 批量生成训练数据
   
   使用强教师模型生成300–500条候选样本。
6. 数据清洗与质量审核
   
   格式筛选、语义审核、人工抽检、去重。
7. 划分训练集与验证集
   
   按题材、人物、故事设定和来源分组隔离。
8. QLoRA 微调
   
   先做小规模训练测试，再正式训练。
9. 固定测试集评估
   
   比较原模型与微调模型，做盲测和自动指标检测。
10. 根据结果迭代
    
    确定是否扩充数据、调整参数，或进入第二阶段。


二、模型底座与训练环境
1. 模型选择
首选
 Qwen/Qwen3-4B-Instruct-2507
模型	第一阶段建议	原因
Qwen3-4B-Instruct-2507	使用	适合直接进行指令微调
Qwen3-4B-Base	暂不使用	更适合先做领域预训练再做指令微调的路线
Qwen3-4B-Thinking-2507	暂不使用	第一阶段不需要额外引入思考模式复杂性

模型地址：
- Qwen3-4B-Instruct-2507
- Qwen3-4B-Base
第一阶段直接在 Instruct 版本上进行 QLoRA，不需要先做全参数微调。
2. Kaggle 硬件策略
按照 T4 ×2、单卡16GB显存的环境设计。
项目	建议
模型	Qwen3-4B-Instruct-2507
微调方法	QLoRA
量化	4-bit NF4
计算精度	FP16
注意力	SDPA
FlashAttention 2	不启用
最大序列长度	2048 起步
LoRA rank	16
LoRA alpha	32
初始学习率	1e-4
Epoch	先训练2轮
Gradient checkpointing	开启

注意：T4 ×2 不等于一张32GB显卡。

普通 DDP 会在两张卡上分别保存模型副本，不会自动把单卡显存合并。第一轮建议先用一张 T4 验证训练流程，确认显存和速度后再考虑双卡。
3. 环境验证
正式训练前先确认：
- GPU型号和显存。
- PyTorch是否识别CUDA。
- Transformers、TRL、PEFT、BitsAndBytes版本。
- Qwen3模型能否正常加载。
- 量化模型能否正常前向计算。
- 训练数据能否正确计算completion loss。
不要为了追求新版本而盲目升级整个环境。先验证版本兼容性，再固定依赖。

三、先制定剧本格式规范
这是整个项目最重要的基础工作之一。

不要先批量生成数据，再试图从生成结果中总结格式。应该先确定目标格式，再让教师模型按照规范生成。
1. 剧本标准结构
建议统一为：
第1集：消失的合同

人物：
张三：公司项目负责人
李四：财务主管
王五：未知身份

场景1｜地点：办公室｜时间：夜｜内景

△ 张三推开办公室的门，发现桌上的合同不见了。

张三：合同呢？

李四：你不是昨天拿走了吗？

△ 张三没有回答，目光落在桌角的监控设备上。

场景2｜地点：监控室｜时间：夜｜内景

△ 张三调出昨晚的监控录像。

张三：把昨天晚上十点到十一点的录像调出来。

李四：你怀疑有人进来过？

△ 画面中，一个戴着帽子的人走进办公室。

【本集悬念】

张三放大画面，发现那个人竟然有自己的脸。


2. 规范必须明确的规则
项目	规则
集标题	第N集：标题
人物表	人物名称及简短身份说明
场景编号	从1开始，连续递增
场景头	固定为地点、时间、内外景
动作描述	使用 △ 开头
人物对白	人物名称：对白内容
集尾悬念	使用固定标记
人物引用	对白和动作中的人物必须有定义
场景数量	按任务要求控制
时长	根据字数、对白和动作节奏估算，不把字数直接等同于实际播放时长

这里有一个需要注意的地方：剧本规范不应把创作本身限制得过死。固定的是机器可解析的结构，剧情表达、对白风格、动作描写应该允许变化。
3. 规范文件
第一份文件：

script_format.md

建议包括：
1. 剧本适用范围。
2. 单集时长和内容要求。
3. 人物表规则。
4. 场景头格式。
5. 动作描述格式。
6. 对白格式。
7. 场景切换规则。
8. 集尾悬念规则。
9. 示例。
10. 不合格示例及原因。

四、建立训练数据标准
建议采用 JSONL，每行一条样本。
1. 训练数据结构
采用 Prompt-Completion 格式：
{
  "prompt": [
    {
      "role": "user",
      "content": "根据以下人物设定和剧情要求，生成一集中文短剧。"
    }
  ],
  "completion": [
    {
      "role": "assistant",
      "content": "第1集：消失的合同\n\n人物：……"
    }
  ]
}


每条样本只包含模型实际需要学习的输入和输出。
2. 元数据独立存储
不要把数据审核信息混入训练文本。建议另建元数据文件，使用稳定的 id 关联：
{
  "id": "single_00001",
  "task_type": "single_episode",
  "source": "synthetic",
  "teacher": "teacher_model_A",
  "review_status": "approved",
  "quality_score": 4,
  "topic": "职场悬疑",
  "split_group": "story_0001"
}


建议保留这些字段：
字段	用途
id	唯一编号
task_type	任务类型
source	人工原创、合成等来源
teacher	生成数据的教师模型
review_status	待审核、通过、拒绝
quality_score	人工质量分
topic	题材
split_group	防止训练集与验证集泄漏
error_type	若为错误修正类数据，记录错误类型

3. 三种任务的数据定义
第一轮建议按以下方式组织：
任务A：单集生成
建议占50%
- 输入：人物设定、背景、剧情目标、时长、风格要求。
- 输出：完整一集剧本。
- 训练重点：完整结构、冲突推进、对白、结尾悬念。


任务B：场景续写与改写
建议占25%
- 输入：已有剧本片段、指定场景、续写或改写要求。
- 输出：指定场景或后续片段。
- 训练重点：人物一致性、上下文衔接、局部冲突。


任务C：按指令修改
建议占25%
- 输入：已有剧本和修改指令。
- 输出：修改后的剧本。
- 训练重点：精确遵循指令，不随意改动无关内容。


比例是第一轮的实验设计，不是固定规律。后续应根据评测结果调整。
4. 数据规模
阶段	样本量	目的
人工金标准	30–50	定义质量和风格
第一批合成数据	300–500	验证训练流程
第二批扩充	1,000–2,000	验证能力是否持续提升
后续规模	5,000–10,000	只有前两轮效果明确时才考虑

不要把样本数量当作质量指标。300条高质量、任务分布合理的数据，可能比3000条重复或低质量数据更有用。

五、人工金标准与教师数据生产
1. 人工金标准
建议先手写30–50条，最好覆盖三种任务。

其中：
- 15–25条完整单集。
- 8–12条场景续写或改写。
- 8–12条指令修改。
这些数据不是简单地让模型模仿某一篇作品，而是建立：
- 剧本结构标准。
- 对白自然度标准。
- 冲突推进标准。
- 动作描写标准。
- 修改任务的边界标准。
如果你的个人创作风格是目标之一，应在人工金标准中明确体现；如果目标是通用短剧能力，则需要多种题材和表达风格，避免只学到单一作者习惯。
2. 教师模型生成策略
教师模型应优先选择创作能力较强的模型，而不是让4B学生模型自己生成大部分训练答案。

生产流程：
任务模板
   ↓
教师模型生成
   ↓
格式校验器
   ↓
语义质量审核
   ↓
重复检测
   ↓
人工抽检
   ↓
合格数据入库


不要只用一个教师模型生成所有数据。可以使用多个不同系列的教师模型，降低单一模型表达习惯带来的风格偏差。
3. 教师生成提示词
建议把以下内容作为教师系统提示词的初始版本：
你是一名专业中文短剧编剧。

你的任务是生成适合1—3分钟视频呈现的中文短剧剧本。

必须遵守以下规则：

1. 严格遵循输入中的人物设定。
2. 不得擅自增加核心人物。
3. 剧本必须具有明确的冲突。
4. 开场尽快进入事件，不要长篇背景介绍。
5. 对白应自然，避免书面化和解释性对白。
6. 动作描述应适合视频拍摄。
7. 场景头必须使用规定格式。
8. 人物对白必须使用“人物名称：对白”格式。
9. 场景编号必须连续。
10. 结尾必须有明确的悬念或情节钩子。
11. 不得输出分析过程。
12. 不得输出剧本以外的解释。

输出必须通过指定的剧本格式校验。


不同任务还应有独立的用户提示词模板，不能把三种任务都压缩成同一条“生成短剧”指令。
4. 数据质量审核
建议分三层：
层级	检查内容	方法
第一层	字段、结构、格式、编号	Python自动校验
第二层	人物一致性、冲突、对白、逻辑	独立裁判模型
第三层	创作质量、风格、实际可拍摄性	人工审核

裁判模型最好不要与教师模型完全相同。

第一批300–500条，建议至少人工审核100–200条，且按任务类别、教师来源和质量分层抽样。不能只检查最容易通过的样本。

拒绝标准：
- 格式错误且无法自动修复。
- 人物身份或关系前后矛盾。
- 对白明显机械化。
- 剧情缺乏有效冲突。
- 续写无法衔接上下文。
- 修改任务擅自更改无关内容。
- 与其他样本高度重复。
- 输出不符合任务要求。
格式合格不代表内容合格。格式校验器不能替代语义审核。

2. dataset_schema.json
它负责检查数据结构，而不是判断剧本写得好不好。

至少应验证：
- id 是否存在且唯一。
- prompt 和 completion 是否存在。
- 消息是否包含合法的 role 和 content。
- prompt 是否包含用户指令。
- completion 是否包含有效输出。
- 元数据字段是否符合预期。
- 是否存在空文本或异常超长文本。
3. validate_dataset.py
建议实现以下检查：
检查项	具体内容
JSON合法性	每行是否为合法JSON
数据字段	必需字段是否齐全
ID	是否重复
任务类型	是否属于三种任务
集标题	是否存在且符合格式
场景编号	是否从1开始连续
场景头	是否包含地点、时间、内外景
人物表	是否定义了剧本使用的人物
对白	是否符合人物名称加冒号的格式
动作	是否符合动作行标记
结尾	是否有集尾悬念标记
长度	是否超出训练序列限制
重复	是否与其他样本高度相似

注意：场景续写、局部改写、指令修改的输出不一定是完整剧本。因此校验器必须根据 task_type 使用不同规则，不能要求所有 completion 都包含完整人物表和集尾悬念。

建议校验器输出：
总样本数：500
JSON合法：500
字段合法：500
格式通过：463
格式失败：37
重复样本：12
超长样本：5
最终候选：451


同时输出错误明细，便于定位和修复。
4. 数据集划分
建议初始采用：
数据集	比例	500条示例
训练集	80%	400
验证集	10%	50
测试集	10%	50

但这里有一个重要限制：

不能简单随机划分。

例如同一个故事的第1集在训练集，第2集在测试集，模型可能已经见过测试内容的关键设定。

建议使用 split_group 分组：
- 同一故事设定放在同一组。
- 同一人物组合尽量放在同一组。
- 同一模板生成的近似样本放在同一组。
- 同一原始作品改写出来的样本放在同一组。
然后按组划分数据集。

另外，测试集必须在训练前冻结，训练过程中不能反复根据测试集结果修改数据，再把它当作独立测试集。
5. 数据长度统计
使用 Qwen3 对最终数据进行实际 Token 统计。

至少统计：
- Prompt Token 数。
- Completion Token 数。
- 总 Token 数。
- P50、P90、P95、最大值。
- 超过2048的样本比例。
- 被截断的 completion 数量。
不要仅凭中文字数判断是否能放入2048 Token。

建议：
- 第一轮先设 max_length=2048。
- 如果 P95 已经接近2048，优先分析长样本。
- 对长样本进行合理拆分或重新设计任务。
- 不要直接截断剧本结尾，尤其不能把结尾悬念截掉。

七、QLoRA训练实施
1. 训练方式
建议使用：
- Transformers：模型加载与分词。
- BitsAndBytes：4-bit量化。
- PEFT：LoRA适配器。
- TRL：SFTTrainer。
- Datasets：数据集加载与处理。
第一轮不需要引入复杂训练框架。
2. 核心参数
参数	首轮建议
LoRA rank	16
LoRA alpha	32
LoRA dropout	0.05
Learning rate	1e-4
Epoch	2
Warmup ratio	0.05
Weight decay	0.01
Max length	2048
Per-device batch size	1起步
Gradient accumulation	8起步
Gradient checkpointing	开启
Optimizer	paged_adamw_8bit
Precision	FP16

这些是实验起点，不是最优参数保证。

LoRA target modules 应先确认模型实际模块名称。不要直接照抄其他架构的配置。对 Qwen3，通常会从注意力投影层开始，再根据训练效果决定是否加入 MLP 投影层。
3. Loss计算策略
这是必须重点验证的环节。

训练目标是：

只让模型对 assistant 的 completion 内容计算损失，不让它学习复述 user prompt。

建议使用 Prompt-Completion 数据格式，并采用 completion-only loss。

需要特别注意：
- TRL 不同版本的默认行为可能不同。
- 如果使用 assistant_only_loss=True，必须确认当前 TRL 版本对 Qwen3 的训练模板是否正确添加 generation markers。
- 不要只看 loss 下降就认定 mask 正确。
- 不要把 prompt、completion 的边界处理交给未经验证的默认配置。
正式训练前必须检查实际 labels：
1. Prompt 对应的 token label 应为 -100。
2. Completion 对应的目标 token 应参与 loss。
3. completion 结束标记 <|im_end|> 应保留在监督目标中。
4. 有效监督 token 数不能为0。
5. 随机抽取若干条样本，解码非 -100 的 label，确认它们对应正确的 assistant 回复。
Qwen3 的训练模板处理依赖 TRL 版本。新版 TRL 对部分 Qwen3 模板提供自动修补，但不能因此省略实际 mask 检查。
4. 训练前的 Smoke Test
不要直接开始训练500条数据。

先完成：
1. 加载模型。
2. 加载4-bit量化。
3. 加载LoRA。
4. 读取5条训练样本。
5. 检查 Tokenization。
6. 检查 labels。
7. 执行5–10步训练。
8. 保存一次 checkpoint。
9. 重新加载 checkpoint。
10. 生成一条测试剧本。
只有上述流程全部正常，才开始正式训练。
5. 训练过程监控
每个 Epoch 至少记录：
指标	用途
Train Loss	观察训练拟合情况
Validation Loss	观察泛化情况
Learning Rate	确认学习率变化
GPU Memory	监控显存
Step Time	监控训练速度
Token Throughput	监控训练效率
Checkpoint	保留可恢复状态

不要只看 Train Loss。

如果训练损失持续下降，而验证损失上升，或者固定测试题的输出质量变差，应怀疑过拟合。
6. Checkpoint保存
至少保存：
- 每个 Epoch 的模型适配器。
- 最佳验证指标对应的适配器。
- tokenizer及相关配置。
- 训练参数。
- 数据集版本。
- 训练日志。
Kaggle 的 /kaggle/working 不应作为唯一保存位置。重要 checkpoint 要及时保存到持久化 Dataset 或其他持久化存储。

第一阶段只需要保存 LoRA Adapter，不必每次都导出完整模型。

八、建立固定评测体系
微调前必须先测试原始模型，否则无法判断微调是否真正有效。
1. 固定测试集
建议建立80道固定测试题，全部对应第一阶段的三种任务。
任务	数量	主要考察内容
单集生成	40	剧情冲突、完整性、结构、结尾
场景续写与改写	20	上下文衔接、人物一致性
按指令修改	20	指令遵循、修改准确性
合计	80	

这80道题不应直接来自训练数据，也不应只是训练样本换一个人物名字。
2. 客观指标
通过 Python 自动评估：
指标	含义
剧本格式正确率	输出是否符合格式规范
场景编号正确率	是否连续、无重复
人物引用错误率	是否出现未定义人物
对白格式正确率	是否符合规定
结尾标记正确率	是否符合任务要求
指令遵循率	是否完成指定任务
截断率	是否出现不完整输出

3. 主观指标
采用1–5分评价：
指标	评价内容
剧情吸引力	是否有吸引观众继续观看的动力
冲突张力	冲突是否明确、有推进
对白自然度	是否像真实人物交流
人物可信度	行为是否符合人物设定
节奏	是否适合1–3分钟短剧
可拍摄性	动作和场景是否能实际拍摄

4. A/B盲测
对同一道题，分别使用：
- A：原始 Qwen3-4B-Instruct-2507。
- B：微调后的 Qwen3-4B。
要求：
1. 使用相同的测试输入。
2. 使用相同的生成参数。
3. 隐藏模型身份。
4. 随机交换 A/B 顺序。
5. 由独立裁判模型评分。
6. 对争议样本进行人工复核。
建议把两个模型的输出顺序交换后再评一次。如果两次评价不一致，记为平局或交给人工复核，不要强行判定胜负。
5. 评测结果必须形成报告
示例：
指标	原始模型	微调模型
格式正确率	72%	94%
人物引用错误率	12%	5%
指令遵循率	68%	83%
对白自然度	3.4	3.8
剧情吸引力	3.2	3.5

以上数字只是报告格式示例，不是实际预测结果。

成功标准不能只有格式正确率提高。 如果模型只是变得更守格式，却失去了原来的创作能力，也不能算成功。

九、训练后的迭代策略
第一轮完成后，不要立即扩大数据量。先根据错误类型决定下一步。
情况A：格式正确率提高，但剧情质量没有提升
说明模型学会了格式，却没有明显学会更好的创作。

处理方式：
- 检查人工金标准是否真正体现了高质量创作。
- 增加高质量冲突、对白和场景推进样本。
- 减少格式重复、内容雷同的样本。
- 检查是否过度强调统一模板。
情况B：完整单集能力提高，但续写能力弱
处理方式：
- 提高场景续写任务比例。
- 增加不同上下文长度的样本。
- 加入人物关系复杂、场景切换频繁的续写任务。
- 重点评估续写是否与前文一致。
情况C：生成能力提高，但修改能力弱
处理方式：
- 增加明确的修改指令。
- 增加局部修改任务。
- 训练模型保留未要求修改的内容。
- 增加修改前后对照样本。
情况D：训练集表现好，测试集表现差
优先排查：
- 数据重复。
- 题材分布过窄。
- 教师模型风格单一。
- 训练与测试数据泄漏。
- 学习率过高或 Epoch 过多。
- 训练样本过少。
不要第一时间增加模型参数量。

十、第二阶段规划
第一阶段的三项任务稳定后，再扩展能力。
第二阶段任务	训练目标
故事大纲生成	建立完整故事结构
人物设计	建立人物动机、关系与行为逻辑
多集连续创作	保持人物、道具、时间线一致
小说改编	将小说内容转换为可拍摄短剧
剧情逻辑审查	识别时间线、人物行为、情节矛盾
错误修正	先提供错误版本，再输出修正版

其中，错误修正任务不建议让教师模型凭空生成低质量剧本。

更合理的方式是：
高质量剧本
    ↓
人工或程序注入指定错误
    ↓
形成错误版本
    ↓
模型识别问题并修正
    ↓
人工检查修正结果
    ↓
形成训练样本


例如：
- 人物突然改变身份。
- 道具在场景切换后消失。
- 人物不知道尚未发生的事情。
- 对白与人物性格冲突。
- 时间线前后矛盾。
什么时候考虑 CPT？
只有在以下情况出现时，再评估 CPT：
- 模型对短剧专业表达掌握不足。
- 现有指令微调无法解决领域语言问题。
- 有足够数量的合法、干净、具有代表性的领域原始语料。
- 有资源承担 CPT 后重新进行 SFT 的成本。
不要因为训练数据少，就认为必须先做 CPT。CPT 和 SFT 解决的问题不同。
什么时候考虑蒸馏？
当第一阶段确认了有效的任务规范、数据标准和评测体系之后，再考虑蒸馏。

4B 模型不应默认作为最主要的教师。更合理的是由能力更强的教师提供高质量样本，再用4B学生模型进行训练。学生模型可以参与数据扩展，但生成结果必须经过质量审核。

十二、关键决策与风险控制
风险	可能后果	控制办法
教师数据质量不稳定	学生学到错误表达	独立审核和人工抽检
单一教师风格污染	输出风格僵化	多教师、多题材
训练样本重复	过拟合	去重和分组划分
Loss mask错误	监督目标错位	检查真实 labels
测试数据泄漏	评测结果虚高	按故事和设定分组
数据格式过严	创作表达受限	结构固定、内容灵活

Kaggle存储丢失	训练成果丢失	及时保存 checkpoint
只看训练 Loss	误判模型能力	使用固定测试集

最重要的判断原则：

这轮实验要回答的不是“4B能不能写短剧”，而是：
1. 现有 Qwen3-4B 是否已经具备基本创作能力？
2. 经过高质量短剧数据微调后，三项指定任务是否有可测量的提升？
3. 提升来自真正的创作能力，还是仅仅来自格式模仿？
4. 300–500条数据是否足以证明这条数据生产和训练路线值得扩大？
如果第一轮不能在独立测试集上证明提升，就先修正数据和训练方案，不要直接扩大到一万条。

下一步应直接进入阶段1： 先产出 script_format.md、dataset_schema.json 和 validate_dataset.py 三个可执行交付物。它们确定之后，再生成教师模型提示词和第一批训练数据。
